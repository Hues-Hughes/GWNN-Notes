# Consolidated Review: Security Concepts (Notes 8.5, 8.5d, 8.5e)

This summary condenses key topics from Asset Management, Authentication Design, and Cryptography.

### 🛡️ I. Asset & System Visibility ([[8.5]])
Focuses on knowing what you have and how to manage it:
- **Asset Discovery Tools:**
    - **Network Scanning (Nmap, Nessus, OpenVAS):** Automatically discover networked devices, open ports, services, and OS details.
    - **Asset Management Systems (Lansweeper, SolarWinds):** Track and catalog hardware, software, and licenses.
    - **MDM (Mobile Device Management):** Manage and secure mobile assets (Intune, Workspace ONE).
    - **Cloud Asset Discovery:** Use cloud-native tools (AWS Config, Azure Resource Graph) to track cloud deployments.
- **Central Repository:** CMB (Centralized repository of information for IT infrastructure).
- **Threat Vector:** Social Engineering (exploiting human psychology).

### 🔑 II. Authentication Design & Factors ([[8.5d]])
Focuses on verifying identity using multiple factors:
- **Authentication Goal:** Select technology ensuring Confidentiality, Integrity, and Availability.
- **Password Management:** Policies are crucial; use **Password Managers** to mitigate risks from reusing passwords across personal/corporate sites.
- **MFA (Multi-Factor Authentication):** Requires two or more distinct factor types.
    - **Something You Know:** Passwords, PINs (Knowledge Factor).
    - **Something You Have:** Smart cards, key fobs, phones generating tokens (Ownership Factor).
    - **Something You Are:** Fingerprints, facial scans, gait analysis (Inherence/Biometric Factor).
    - **Somewhere You Are:** Location data (IP address or GPS) used for verification.
- **Advanced Concepts:**
    - **Biometrics:** Involves *Enrollment* $\rightarrow$ Template Creation $\rightarrow$ Re-scan Comparison.
    - **Hard Tokens:** Devices generating unique signed tokens (e.g., Certificate-Based).
    - **Soft Tokens:** OTPs via SMS/Email (Note: These are often considered two-step verification, not true MFA ownership factors).
    - **Passwordless:** Eliminating knowledge-based factors entirely (e.g., FIDO2/WebAuthn).

### 🔐 III. Cryptography Fundamentals ([[8.5e]])
Focuses on securing data through encoding:
- **Cryptography vs. Obscurity:** Cryptography is mathematically secure; obscurity relies on secrecy, which is unreliable.
- **Symmetric Encryption:** Uses a *single secret key* for both encryption and decryption (Confidentiality). Key management is critical.
- **Asymmetric Encryption:** Uses a *key pair*: a public key (for encrypting) and a private key (for decrypting). Only the paired private key can read the message encrypted with the public key.
- **Hashing:** A one-way function that produces a fixed-length digest from any input. Used primarily to prove **Integrity** (impossible to recover plaintext from the hash, low chance of collision).
- **Digital Signatures:** Uses asymmetric cryptography and hashing to prove *authenticity* and *integrity*.
- **PKI & Trust:**
    - **Certificate Authority (CA):** Issues digital certificates.
    - **Digital Certificate:** A wrapper containing a subject's public key, signed by the CA.
    - **Root of Trust:** The self-signed certificate at the top of the trust chain.
